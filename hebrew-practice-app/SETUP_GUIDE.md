# מדריך הקמה למורה — אפליקציית תרגול לתלמידים

מדריך זה מיועד למורה **ללא ידע בתכנות**. יש לבצע את הצעדים לפי הסדר.
לוקח כ-15 דקות בפעם הראשונה.

---

## שלב 1 — יצירת גיליון Google Sheets

1. היכנסו ל-[sheets.google.com](https://sheets.google.com) ופתחו גיליון חדש וריק.
2. תנו לו שם, למשל: **"תרגול תלמידים - נתונים"**.
3. שמרו את כתובת ה-URL של הגיליון בצד — נזדקק לה בהמשך.

---

## שלב 2 — הדבקת קוד ה-Apps Script

1. בתוך הגיליון: תפריט **תוספים (Extensions) ⟵ Apps Script**.
2. יפתח עורך קוד עם קובץ ברירת מחדל בשם `Code.gs` — מחקו ממנו את התוכן הקיים.
3. בפרויקט הזה יש **4 קבצי קוד** בתיקייה `apps-script/`. יש להעתיק כל אחד לעורך:
   - `Code.gs` — הדביקו לתוך `Code.gs` הקיים.
   - `Config.gs` — לחצו על סימן ה-`+` ליד "Files" ⟵ Script ⟵ תנו שם `Config` ⟵ הדביקו.
   - `SheetService.gs` — צרו קובץ נוסף בשם `SheetService` ⟵ הדביקו.
   - `Utils.gs` — צרו קובץ נוסף בשם `Utils` ⟵ הדביקו.
4. לחצו על סמל **השמירה** (💾) למעלה.

### הרצה חד-פעמית שיוצרת את לשוניות הנתונים אוטומטית

1. בחלק העליון של העורך, מהתפריט הנפתח שבו רשומות הפונקציות, בחרו **`setupSheets`**.
2. לחצו **Run (הרצה)**.
3. בפעם הראשונה Google תבקש הרשאות — לחצו **Review permissions**, בחרו את חשבונכם,
   ולחצו **Advanced ⟵ Go to (שם הפרויקט) ⟵ Allow**. זה בטוח: זהו קוד ששייך לכם בלבד.
4. חיזרו לגיליון — אמורות להופיע 3 לשוניות: **Topics**, **Questions**, **Results**, עם כותרות
   ושורות דוגמה בעברית.

> אם אתם מעדיפים למלא את הנתונים בעצמכם, אפשר לדלג על ההרצה וליצור את הלשוניות
> ידנית לפי המבנה בשלב 4 למטה, או לייבא את קובצי ה-CSV מהתיקייה `sheets/`
> (תפריט קובץ ⟵ ייבוא, לכל לשונית בנפרד).

## שלב 3 — פריסה כ-Web App (Deploy)

1. בעורך ה-Apps Script: **Deploy (פריסה) ⟵ New deployment (פריסה חדשה)**.
2. ליד "Select type" לחצו על גלגל השיניים ⟵ בחרו **Web app**.
3. הגדרות הפריסה (חשוב!):
   - **Execute as (הרצה בתור):** `Me` (החשבון שלכם) — כך שהאפליקציה תוכל לקרוא/לכתוב
     לגיליון גם כשהתלמיד לא מחובר לחשבון גוגל.
   - **Who has access (מי רשאי לגשת):** `Anyone` — כדי שתלמידים יוכלו לגשת בלי להתחבר.
     (זהו MVP ללא התחברות תלמידים, כנדרש; אין בגיליון מידע רגיש מעבר לשם ות.ז. לצורך זיהוי בלבד.)
4. לחצו **Deploy**, אשרו הרשאות אם מתבקש.
5. תקבלו **Web app URL** שנראה כך:
   `https://script.google.com/macros/s/AKfycb.../exec`
   **העתיקו כתובת זו** — היא תשמש בשלב הבא.

> **חשוב:** בכל פעם שאתם משנים את קוד ה-Apps Script (לא את תוכן הגיליון —
> רק את הקוד עצמו), יש לבצע **Deploy ⟵ Manage deployments ⟵ ✏️ ⟵ New version ⟵ Deploy**
> כדי שהשינויים ייכנסו לתוקף. שינויים בתוכן הגיליון (הוספת שאלות וכו') לא דורשים פריסה מחדש.

---

## שלב 4 — חיבור הממשק (Frontend) לגיליון

1. פתחו את הקובץ `frontend/js/config.js`.
2. מצאו את השורה:
   ```js
   API_URL: 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE',
   ```
3. הדביקו במקומה את ה-URL שקיבלתם בשלב 3, כך:
   ```js
   API_URL: 'https://script.google.com/macros/s/AKfycb.../exec',
   ```
4. שמרו את הקובץ.

### איך להריץ את הממשק

יש שתי אפשרויות פשוטות:

- **הצגה מקומית מהירה:** פתחו את `frontend/index.html` בלחיצה כפולה בדפדפן. מספיק לבדיקה.
- **פרסום אמיתי לתלמידים (מומלץ):** העלו את תוכן תיקיית `frontend/` לאחסון סטטי חינמי,
  למשל **GitHub Pages**, **Netlify** או **Google Sites עם קובץ מוטמע** — ושילחו לתלמידים
  את הקישור שיתקבל. אין צורך בשרת — זהו HTML/CSS/JS סטטי בלבד.

## שלב 5 — ניהול נושאים ושאלות (בלי לגעת בקוד, אף פעם)

### לשונית Topics — נושאים

| עמודה | הסבר |
|---|---|
| `topic_id` | מזהה קצר וייחודי (למשל `t1`). **חייב** להיות זהה לעמודת `topic_id` בלשונית Questions. |
| `topic_name` | השם שהתלמיד רואה על המסך. |
| `questions_per_quiz` | כמה שאלות יוגרלו לתלמיד מתוך כל השאלות הפעילות בנושא. |
| `active` | `TRUE` כדי להציג לתלמידים, `FALSE` כדי להסתיר נושא זמנית. |

- **להוסיף נושא חדש:** הוסיפו שורה חדשה בתחתית הטבלה.
- **להשבית נושא:** שנו `active` ל-`FALSE`. הוא ייעלם מרשימת הבחירה של התלמידים מיד
  (בפעם הבאה שהם טוענים את הדף).
- **לשנות כמות שאלות בנושא:** שנו את המספר בעמודת `questions_per_quiz`. אין צורך בקוד.

### לשונית Questions — שאלות

| עמודה | הסבר |
|---|---|
| `question_id` | מזהה ייחודי לשאלה (למשל `q27`). |
| `topic_id` | לאיזה נושא השאלה שייכת (חייב להתאים בדיוק ל-`topic_id` בלשונית Topics). |
| `question_text` | נוסח השאלה. |
| `option_a` … `option_d` | ארבע האפשרויות. ניתן להשאיר `option_d` ריק אם רוצים רק 3 אפשרויות. |
| `correct_answer` | האות של התשובה הנכונה: `a`, `b`, `c` או `d`. אפשר גם להקליד את הטקסט המלא של התשובה הנכונה במקום האות. |
| `active` | `TRUE` כדי שהשאלה תשמש בתרגולים, `FALSE` כדי להשבית אותה. |

- **להוסיף שאלה:** שורה חדשה בתחתית הטבלה, עם `question_id` חדש וייחודי.
- **להסיר שאלה זמנית:** שנו `active` ל-`FALSE` (עדיף על מחיקת השורה, כדי לשמור היסטוריה).
- **לערוך שאלה:** פשוט שנו את הטקסט בתא הרלוונטי — הכל נטען מהגיליון בכל תרגול.

> הסדר של השאלות ושל האפשרויות (א/ב/ג/ד) על המסך **מוגרל מחדש בכל ניסיון** של תלמיד,
> אז אין צורך "לערבב" ידנית בגיליון.

### לשונית Results — תוצאות

נבנית אוטומטית. כל שורה = ניסיון תרגול אחד של תלמיד. אין לערוך אותה ידנית;
אפשר לסנן/למיין/לייצא אותה לצרכי מעקב.

## פתרון תקלות (Troubleshooting)

| תופעה | סיבה אפשרית ופתרון |
|---|---|
| "האפליקציה עדיין לא חוברה לגיליון" | לא הדבקתם את ה-URL הנכון ב-`config.js`, או שהוא עדיין `PASTE_YOUR_APPS_SCRIPT...`. |
| מסך לבן / "שרת החזיר תשובה לא תקינה" | כתובת ה-URL שגויה, או שהפריסה (Deployment) לא הוגדרה כ-Web App עם "Anyone". בדקו שוב את שלב 3. |
| "Sheet tab ... was not found" | שם הלשונית בגיליון לא תואם בדיוק ל-`Topics` / `Questions` / `Results` (רגיש לאותיות גדולות/קטנות). |
| "Sheet ... is missing required column" | כותרת עמודה בשורה 1 נמחקה/שונתה בטעות. השוו לטבלאות שבמדריך זה. |
| רשימת הנושאים ריקה אצל תלמיד | כל הנושאים מוגדרים `active = FALSE`, או שעמודת `topic_id` ריקה בשורה. |
| "אין שאלות פעילות בנושא זה" | לכל השאלות של אותו `topic_id` יש `active = FALSE`, או שאין שאלות עם אותו `topic_id`. |
| שינוי בקוד לא נכנס לתוקף | שכחתם לעשות **Deploy ⟵ Manage deployments ⟵ New version** אחרי עריכת קובצי ה-`.gs`. |
| שגיאת CORS בקונסולת הדפדפן | ודאו שלא שיניתם את שיטת השליחה ב-`api.js` — הבקשות חייבות להישאר GET רגיל, ו-POST עם `Content-Type: text/plain`. |
| תוצאה לא נשמרת בגיליון | בדקו שהלשונית `Results` קיימת ושהכותרות בשורה 1 תואמות בדיוק לרשימה שבמדריך. |

## הערות חשובות על גבולות ה-MVP (בכוונה!)

- אין הרשמה/סיסמה לתלמידים — השם ות.ז. משמשים לזיהוי בתוצאה בלבד, לא לאימות.
- הבדיקה והניקוד מתבצעים בצד הדפדפן של התלמיד (client-side) — מתאים לתרגול לימודי
  ולא למבחן בעל משקל (high-stakes), כפי שצוין בדרישות.
- אין טיימר, אין רמות קושי, אין AI — בכוונה, כדי לשמור על מערכת פשוטה שמורה יכול
  לתחזק בעצמו דרך הגיליון בלבד.
